# Plan: TTL-based ban cache

## Goal
Eliminate per-request DB queries for ban checks by loading ban lists into memory. TTL-based expiration handles both admin API and CLI-triggered changes.

## Data structures

| Ban list | Structure | Rationale |
|---|---|---|
| IP ranges | `BTreeMap<u32, u32>` (start → end) | O(log n) lookup via binary search, handles 100k+ ranges |
| Extensions | `HashSet<String>` | O(1) lookup, small list |
| MIME types | `HashSet<String>` | O(1) lookup, small list |
| File hashes | `HashSet<Vec<u8>>` | O(1) lookup, small list |
| User agents | `Vec<String>` | O(n) scan (LIKE '%pattern%'), small list |

## Files

### New: `src/cache.rs`

**`BanCache` struct:**
```rust
pub(crate) struct BanCache {
    pool: DbPool,
    data: RwLock<BanData>,
    last_reload: AtomicU64,  // unix timestamp in seconds
    ttl_secs: u64,
}
```

**`BanData` struct (inside RwLock):**
```rust
struct BanData {
    ip_ranges: BTreeMap<u32, u32>,
    extensions: HashSet<String>,
    mimes: HashSet<String>,
    hashes: HashSet<Vec<u8>>,
    user_agents: Vec<String>,
}
```

**Methods:**
- `new(pool: DbPool, ttl_secs: u64) -> Self` — creates cache, immediately reloads
- `is_expired(&self) -> bool` — checks if `now - last_reload > ttl_secs`
- `async fn reload(&self)` — acquires write lock, queries DB for all ban lists, replaces data
- `is_ip_banned(&self, ip: u32, ban_type: BanType) -> bool` — read lock, binary search
- `is_extension_banned(&self, ext: &str) -> bool` — read lock, HashSet lookup
- `is_mime_banned(&self, mime: &str) -> bool` — read lock, HashSet lookup
- `is_hash_banned(&self, hash: &[u8]) -> bool` — read lock, HashSet lookup
- `is_user_agent_banned(&self, user_agent: &str) -> bool` — read lock, Vec scan

**Reload queries:**
- IP ranges: `SELECT start_ip, end_ip FROM banned_ipv4_ranges WHERE (expires_timestamp IS NULL OR expires_timestamp > NOW())` — builds BTreeMap, filtering expired entries
- Extensions: `SELECT extension FROM banned_file_extensions` — builds HashSet
- MIMEs: `SELECT mime FROM banned_file_mimes` — builds HashSet
- Hashes: `SELECT hash FROM banned_file_hashes` — builds HashSet
- User agents: `SELECT pattern FROM banned_user_agents` — builds Vec

## TTL value

**300 seconds (5 minutes).** Rationale:
- CLI blacklist sync runs daily by default — 5 min staleness is acceptable
- Admin actions get immediate effect via `cache.reload()` call
- Short enough to pick up CLI changes reasonably quickly
- Long enough to avoid unnecessary DB hits during normal operation

## Reload strategy

**Lazy reload:** Each handler checks `is_expired()` before performing ban checks. If expired, calls `reload()` (acquires write lock, queries DB, replaces data). Subsequent requests during reload wait on the read lock and see stale data until reload completes.

This avoids a background task and keeps the code simple. The first request after TTL pays the reload cost; subsequent requests during the TTL window are zero-DB-cost.

## DB query reduction

**Before:**
- Upload (single file): 5 queries
- Download: 1 query

**After (during TTL window):**
- Upload: 0 queries (all in-memory)
- Download: 0 queries

**After (during reload):**
- Upload: 1 query (the reload fetches all 5 lists in ~5 queries, but only once)
- Download: 1 query (same reload)

With 100k IP ranges, reload takes ~5 DB queries but serves all subsequent requests for 5 minutes without any DB hits.
